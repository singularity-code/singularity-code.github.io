Claude Code '다시 묻지 않기'가 비밀번호를 평문으로 저장: 공개 GitHub 저장소 1,122개 파일에서 시크릿 발견

보안 업체 Apiiro가 Claude Code의 승인 기능이 명령어째로 저장하는 설정 파일을 공개 저장소에서 조사했다. 명령에 섞여 들어간 비밀번호와 토큰이 그대로 남아 있었다.

The Hacker News(11월 7일자)에 따르면, 명령 승인창에서 "Yes, and don't ask again"을 고르면 Claude Code가 그 명령 전체를 프로젝트의 .claude/settings.local.json에 저장한다. 명령에 비밀번호나 토큰이 들어 있으면 그것도 평문으로 남고, 이후 세션에서는 일치하는 명령이 묻지 않고 실행된다. 팀이 일부러 커밋하는 .claude/settings.json에서도 같은 일이 생기는 경우가 있다고 한다.

Apiiro의 조사 결과는 이렇다. 공개 저장소 약 103,617곳에서 이 파일 약 104,185개를 찾았고, 그중 1,122개(약 1.1%)에 시크릿이 하나 이상 있었다(고유 1,379개). 데이터베이스 비밀번호 379개, SSH 로그인 43개, GitHub·GitLab·npm 토큰 42개, AWS 키 23개가 포함됐다. Apiiro는 이 값들이 아직 유효한지는 시험하지 않았다. 이전 git 이력과 공유 설정, 대화 로그까지 합치면 1,994개 저장소에서 2,539개다. gitleaks는 1,122개 중 564개, TruffleHog는 643개만 잡아냈고 215개는 둘 다 놓쳤다.

앤트로픽의 대응에 대해서는 Apiiro 쪽 주장만 확인했다. Claude Code가 이 파일을 사용자의 전역 git 제외 목록에는 넣지만 프로젝트의 .gitignore에는 넣지 않아 다른 사용자에게는 보호가 이어지지 않는다는 것이다. 2025년 8월에 올라온 관련 버그 리포트는 자동화 봇이 2026년 1월 "not planned"로 닫았고, 연구자들은 앤트로픽의 답변을 받지 못했다고 한다. 앤트로픽의 입장은 확인하지 못했다. 권고는 조직 저장소와 git 이력에서 두 설정 파일을 찾고, 들어 있던 자격 증명을 먼저 교체한 뒤, 로컬 파일을 추적에서 빼 .gitignore에 넣으라는 것이다. 명령에는 시크릿을 직접 쓰지 말고 환경 변수 참조를 쓰라고도 한다.
