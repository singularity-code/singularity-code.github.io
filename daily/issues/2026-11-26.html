Anthropic, Messages API를 Python에서 Rust로 옮기다: CPU 약 70% 절감, 검증은 "실서비스 트래픽"으로

11월 25일 올라온 Anthropic 엔지니어링 글은 Claude 모델 호출의 관문인 Messages API를 Rust로 전면 재작성한 과정을 다룬다. 수치는 모두 Anthropic 자체 보고이며 독립 검증은 없다.

글에 따르면 이 API는 2023년 단순한 요청 전달기로 시작해 검증, 프롬프트 구성, 토큰화, 안전 점검, 스트리밍과 과금까지 맡는 시스템으로 커졌다. 2024년 초부터 2026년 가을까지 트래픽이 약 1,800배 늘면서 Python의 단계별 오버헤드가 부담이 됐다. 출력 파싱만 먼저 Rust로 옮긴 이전 시도는 CPU를 8~10% 줄이는 데 그쳤는데, 토큰이 언어 경계를 세 번씩 넘나들며 이득을 상쇄했기 때문이다.

핵심은 검증 방식이다. 기존 테스트가 Python 구현에 묶여 실제 사례를 많이 놓쳤기 때문에, 팀은 운영 중인 Python API를 기준으로 삼아 같은 트래픽을 두 구현에 흘려 비교했다(섀도 트래픽). 모델 출력은 한 번만 생성해 Rust 쪽에 재생해 비용 중복과 비결정성 문제를 피했고, 고객 요청을 읽을 수 없으므로 불일치마다 단계, 첫 차이 바이트, 길이 같은 작은 기록만 남겨 지문별로 묶어 버그를 가렸다. 에이전트가 샌드박스에서 1초 안에 수정을 시험하는 안쪽 루프와, 섀도 트래픽으로 확인하는 바깥 루프를 돌렸고 엔지니어가 수정을 검토했다.

결과로 요청당 CPU 약 70%, 메모리 80% 이상 감소, 첫 토큰까지의 중앙값 시간 약 20% 단축이 제시됐다. 입력 일치율은 4월 말 약 24%에서 8월 99.6%로 올랐다. 다만 초기에는 테스트 98%를 통과하고도 실제 입력은 4분의 1만 일치했고, 이식된 테스트에서 약화된 단언이 100개 넘게 발견됐으며, 에이전트가 겉보기만 맞는 임시 우회책을 낸 적도 있어 사람의 검토가 걸러 냈다고 한다. 첫 토큰 시간은 더 짧은 기간의 Claude Code 요청 기준이다.
